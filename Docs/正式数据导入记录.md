本次明确的可调参数：轻度夜间扩散 +2；假顾客当前服务期间每秒 +1 污染，单个最多 +5；篡改书阅读额外污染 +2；返架污染书阅读／售卖额外污染 +3；没有可返架书时污染 +5；永久租金每次 +10、累计上限 +30，永久客流每次 −1、累计上限 −2。守夜同一来源的永久费用和漏洞不重复堆叠。

闭架解锁只从仍在库的“篡改且封存”副本中选择；存在多册历史篡改书时在这个集合内随机选择。若符合条件的书已售出或被焚毁，不解锁其他正常书，但独立的 +10 污染照常执行。

律令延迟为 2 个后续结算点，冷却为 3 个结算点；夜结及污染上跨阶段推进。`bStageCrossTriggersLoophole=false`，避免旧版“另外随机触发漏洞”与新的回合推进重复叠加。候选数量轻度 3、中度 4、重度 4。应急卡由程序提供，不伪装为第八条策划律令。

## 创建与验证方式

此处使用 C++ Commandlet 驱动 UE 保存原生 `.uasset`；不是通过改文件后缀生成资源，也不要求人工逐行录入。编辑器关闭并完整编译后执行：

```powershell
& 'D:/epic/UE_5.1/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' 'D:/unreal_project/Libary_release/Libary_Release.uproject' -run=ShopReleaseData -unattended -nop4 -NullRHI
```

重新启动一个独立进程验证磁盘加载：

```powershell
& 'D:/epic/UE_5.1/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' 'D:/unreal_project/Libary_release/Libary_Release.uproject' -run=ShopReleaseData -VerifyOnly -unattended -nop4 -NullRHI
```

生成器先检查所有八个目的资源，任意一个已存在就拒绝写入；没有强制覆盖参数。`-VerifyOnly` 只读取并校验现有表。写入前调用 `ConfigureTables` 和 `ValidateConfig`；生成后再次校验；独立进程的 VerifyOnly 才是磁盘重载的验证。

`bRequireCoreContentCounts=true` 检查本轮核心正式内容；`bRequireFinalContentCounts=false`，因为用户明确延期历史、程序 B 的内容尚未接入。`bEnableHistory=false`、`bEnableMarket=false`，不在空表上伪造成功。

如果未来已在 UE 中调整数据，不能重跑生成器覆盖这些修改。直接在 UE DataTable 编辑器调整并保存，随后运行 VerifyOnly。若首次保存中途失败，日志会报告此前已写入的表；不要绕过覆盖保护，先人工核对目的目录再决定恢复方案。
