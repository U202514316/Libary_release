# 控件蓝图闭环使用说明

适用工程：`D:\unreal_project\Libary_release\Libary_Release.uproject`，UE 5.1。本说明对应 `/Game/ProgramA/UI` 下本轮新建的可编辑界面。旧文档中的夜间表店营业流程不适用于这里的 UI 专用规则。

当前入口流程为：**主菜单 → 猫头鹰开场引导 → 白天接待 3 位顾客 → 白天结算 → 夜间进货／里店上架二选一 → 夜间结算 → 次日**。正常期限为 35 天，污染或经营失败可以提前触发结局；结局页可以重开。

**2026-10-06 当前人物更新：**每天三位顾客的立绘不重复，普通 4 图、急躁 1 图、秘密 1 图、污染 2 图；主角仍用男装，商人改为新提供的尖帽提灯人物 `T_Merchant`。女装备用、猫头鹰保持不变。43 项经营自动化通过；最终界面回归为 **38,134 项检查、0 失败，92 张实际渲染，0 错误、0 警告**。35 天与四结局回归通过；污染释放、污染顾客专项截图采用明确标记的临时测试配置，不改保存的业务数值。律令未完成项见第 5 节。

## 1. 打开并运行

1. 用 UE 5.1 打开工程，在内容浏览器进入 `Content / ProgramA / UI / Maps`。
2. 双击 `L_BookstoreUI`，点击工具栏 **Play / 运行**。仅打开某个 WBP 的 Designer 预览不会运行经营流程。
3. 主菜单点击“开始”，逐条阅读开场引导；最后一条完成时才调用 `RequestNewRun`。引导期间业务状态仍是 `Boot`，没有顾客，也不扣耐心。
4. 新一天先显示一层场景、顶栏和收银台处的男装主角立绘。等待 2–4 秒，顾客人物出现在店内；点击人物后才显示需求和“观察／售卖／拒绝”操作，再打开书架选书。每位顾客离开后，下一位也需等待 2–4 秒。处理完当天最后一位顾客后，逻辑自动进入白天结算，不需另写一次结算。
5. 夜间选择商人后，先看到集市场景与尖帽提灯商人的专属立绘；点击商人打开采购面板，再点击书卡购买。关闭采购面板会回到商人场景；“完成进货”始终可用于结束夜晚，下次进入商人页重新从场景开始。

入口地图已使用 `Framework/BP_UIGameMode`，它指定 `BP_UIPlayerController`。后者的 `Root Widget Class` 指向 `WBP_UIRoot`。这个 GameMode 的 `bStartNewRunOnFirstEntry=false`，保证主菜单与引导先出现。

`ShopPlayerController`负责创建、加入屏幕并注册根控件，退出时注销。**不要在关卡蓝图、根控件 Construct 或子页面中再创建一次 Root、重复 RegisterView，或提前调用 RequestNewRun。** `ShopRunSubsystem`由 GameInstance 自动创建，整局只有一份经营状态，不必更换现有 GameInstance。

## 3. 按钮和接口怎样连接

业务按钮的一般节点链是：`OnClicked → Get Shop Service → 对该对象调用 Request… → GetLastResult → FormatCommandResult → 显示 Feedback`。**Service 节点的 Target 是 Get Shop Service 的返回对象，不是 Self、PlayerController 或某个子控件。**

| 页面／操作 | 已使用的调用 | 注意事项 |
| --- | --- | --- |
| 主菜单“开始” | `BPI_UIFlow.ShowTutorial`，Target 为 `GetRootView` | 只切换界面，不开局。 |
| 引导“下一条” | 蓝图更新 `DialogueIndex`；最后调用 `RequestNewRun()` | 返回 `bool`；只允许在 `Boot/End`新开一局。 |
| 主菜单“退出” | `QuitGame` | 在编辑器中结束当前游玩。 |
| 点击顾客人物 | 透明 `BtnPortraitHit` 设置 `bCustomerSelected=true` | 仅到场人物可点击；没有可见的“点击顾客”按钮。选择后 `NeedPanel/InteractionPanel`展开，点击本身不观察、不售卖、不跳过顾客。 |
| 打开书架 | `GetCurrentCustomerIndex → RequestBeginSell(Index)` | 返回动作枚举；`Opened`表示进入选书。当前队首不是 `GetActiveCustomerIndex`，后者仅在选书期间有效。 |
| 观察／拒绝 | `RequestObserveCustomer(Index)`／`RequestRejectCustomer(Index)` | 只操作当前未完成队首；返回 `FShopCommandResult`。观察后才揭示假顾客身份。 |
| 出售书卡 | `RequestSell(BookId)` | `Sold`才算卖出。现规则选错书会结束该次接待，不扣这本书的库存，也没有售书收入。 |
| 取消选书 | `RequestCancelSell()` | 返回 `bool`；关闭选书并回到当前顾客，不结束接待。 |
| 白天结算“继续” | `RequestContinue()` | `DayEnd → DuskChoice`。 |
| 夜间“商人” | `RequestOpenRestock()` | 这是普通书进货，不能改接黑市 `RequestOpenMarket`。 |
| 点击商人／关闭采购 | `BtnMerchantHit`展开 `PurchasePanel`／`BtnClosePurchase`关闭它 | 只改变商人页界面状态，不购买、不退出 `Restock`；`BtnDone`始终可结束夜晚。 |
| 购买普通书 | `RequestRestock(BookId)` | 返回 `bool`；扣 `Cost`并加一册，资金不足失败。 |
| 夜间“里店” | `RequestOpenInside()` | 与商人互斥；这里不生成顾客。 |
| 上架／撤回 | `RequestListSecretBook(BookId)`／`RequestUnlistSecretBook(BookId)` | 返回命令结果；只切换一册的位置，不增加拥有总量。 |
| 完成进货／上架 | `RequestEndNight()` | 夜结只执行一次，随后显示 `NightEnd`。 |
| 夜间结算“继续” | `RequestContinue()` | 进入次日；第 35 天结算后进入最终结局。 |
| 选择律令 | `GetCandidateId(Index) → RequestEnactDecree(DecreeId)` | 先由 `CanChooseDecree`显示可用状态；执行时 C++ 仍重新检查阶段和资源。 |
| 暂不颁布 | `RequestSkipDecree()` | 恢复被打断阶段，污染不会因此自动降低。 |
| 结局“重开”／“主菜单” | `RequestNewRun()`／`BPI_UIFlow.ShowMainMenu` | 重开重置整局；返回菜单只切页面，再开始会重新经过引导。 |

三种返回形式不能混用：`bool`看真假；`EShopActionResult`区分 `Opened/Sold/WrongBook/NoMatch`等；`FShopCommandResult`含 `bSucceeded、Code、Message、SubjectId`。统一提示可读取服务的 `GetLastResult/GetLastError`。按钮灰显只是提示条件，C++ 的实际返回结果才决定操作是否完成。

根控件的 `RefreshShop`通过 `GetPhasePageIndex`更新页面；`NewDay`和 `ResolveCustomer`重置顾客交互，后者通过 `FormatCustomerResult`显示接待结果。接待回调中的 `Rejected`表示“已谢绝这位顾客”，不能和通用命令失败混为一谈。`ShowDecreeResult/ShowObserveResult`在公共提示区显示律令与观察结果；返回菜单、教程、新一天及 `ShowEnding`时清除旧提示，结局页不会保留上次售卖或拒绝的 Toast。不要在这些刷新回调里同步发起新的经营命令，服务通知期间禁止命令重入。污染打断后的页面恢复也由状态决定，不要在颁布律令后写死回白天。

商人页使用页面进入判断重置：`RefreshShop`在 `SetActiveWidgetIndex`之前比较旧页与目标页，只有 `old != 6 && new == 6`时才调用 `MerchantPage.ResetMerchant`。购买后仍为第 6 页，刷新不会关闭已打开的采购面板；离开后下次进入则重置。不要每次 `RefreshShop`都重置，也不要改挂黑市专用 `OpenMarket`回调；这两个页面虽然共用索引映射，当前普通书商人的业务阶段仍是 `Restock`。

到场计时由 C++ 维护。`IsCurrentCustomerPresent()`及快照 `bCustomerPresent/CustomerArrivalRemaining`分别表示是否到场和剩余等待时间；等待期间 `GetCurrentCustomerIndex`返回 `-1`，`GetCustomers`中可以已有排队记录，不能据此提前显示人物或调用售卖。到场的这一帧不扣耐心，后续计时才影响当前顾客。`CustomerGroup`的可见性取决于是否到场；`NeedPanel/InteractionPanel`还要求 `bCustomerSelected=true`。`ResetCustomer`清除此选择，因此新客刚到场时也不会自动展开面板。

## 4. 本轮经营规则和调参

在 **Edit → Project Settings → Game → Bookstore** 中，`Run Rules`选择 `/Game/ProgramA/UI/Data/DT_RunRules_UI`，`Decrees`选择同目录 `DT_Decrees_UI`。其余六个引用继续使用 `/Game/ProgramA/Release/Data`。两张 UI 表是独立副本；原 Release 表和原 ProgramB 资产不由本轮生成器覆盖。

打开 `DT_RunRules_UI` 的 `Default`行可调资源参数。主要设置如下：

| 字段 | 当前 UI 初始配置／含义 |
| --- | --- |
| `bDaytimeOnlyLoop` | `true`：每天固定 3 个顾客槽位，只有白天交易。 |
| `bUseCustomerArrivalDelay`、`CustomerArrivalMin/Max` | UI 表为 `true`、`2/4` 秒，首位及每位后继顾客独立等待；C++ 默认关闭以兼容旧表。 |
| `CustomersMin/CustomersMax`、`WeekTwoCustomerBonus`、`InsideCustomers` | `3/3`、`0`、`0`；新模式直接固定 3 槽，不受周加成或永久客流减少影响。 |
| `bAllowEarlyClose` | `false`：处理完当天队列再结算；成交、拒绝、缺货离开和耐心耗尽均可结束一次接待。 |
| `StartPsychic`、`NightlyPsychicGain`、`PsychicMax` | 开局 8；每晚恢复 8；最高 100。 |
| `NightlySecretSupply`、`SecretOwnedCap` | 每晚合计补 1 册，秘密书拥有总数达到 7 时不再补。 |
| `MaxDays`、`Rent`、`RentTiming` | 35 天、房租 25、白天结束时收租；实际以表值为准。 |
| `bEnableHistory/bEnableMarket` | 均为 `false`。 |

补给按“当前拥有数量最少，再按 BookId 稳定排序”选书。新副本封存、未读、未污染、**未上架**；已上架副本跨日保留。补给与夜结是同一事务，重复点击不能再获得一次。夜结直接恢复灵能不受旧阅读灵能倍率影响。本 UI 没有翻阅或消耗灵能收书按钮。

第一天秘密书虽然已经拥有，但没有上架，因此不会生成秘密顾客。之后秘密顾客按角色权重进入白天队列，数量不超过已上架秘密册数，且受唯一帽兜立绘限制每天最多 1 位；有货不保证每天必来。普通、急躁、污染顾客买普通书；污染顾客需达到中度门槛 61，初始耐心 20 秒，可观察、拒绝或售卖，使用两张污染立绘。帽兜神秘人初始耐心 30 秒，只买上架的秘密书，基础售卖污染 +10；污染 ≥61 时全体耐心按 1.3 倍流失。污染顾客的额外交易污染参数 `PollutionOnPollutedCustomer`当前为 0，观察文案已去除必加污染的误导。假顾客使用普通外观，替换队首之后的等待槽位时会选择当天未占用的立绘，没有位置时延后，不追加第四位。

秘密书上架不扣钱、不加污染。其 `BookType=Secret`、`Layer=Inside`表示商品类别和来源，**不要为了在表店出售而改成 Table**。实际可售数量看 `ListedCopies`，总拥有数量看 `Stock`，存放数量看 `StoredCopies`。出售优先取已读且已上架副本，扣一册并按 `Price`记收入；秘密书基础售卖污染为 10，污染返架本另加 3，其他有效效果可以继续修正。修改书籍价格、进货价、简介使用 `DT_Books`，不要在按钮蓝图里另写一次收支。

最后一位顾客若同时触发污染弹窗，C++ 已完成售卖和一次收租，先显示 `WBP_Decree`，处理后恢复 `DayEnd`。夜间仅有进货或里店管理；`RequestOpenTableShop`在新模式被拒绝，不能用它作为“完成夜间活动”的按钮。

35 天是正常经营期限，不是所有结局都必须等到第 35 天。`DT_Endings`保留四种结局：连续 3 个结算日资金为负时关门；污染达到 100 时污染释放；第 35 天夜结后，启蒙至少 60 且污染低于 60 时归还，否则守旧循环。归还不另要求资金达到 1500，不创建第 36 天。结局页同时显示实际触发条件和本局最终天数、资金、污染、启蒙。

## 5. 七条律令与 UI 专用代价

污染达到新的阶段时出现正式律令候选；候选根据污染阶段、灵能、资金及其他可支付条件过滤。没有可选正式律令时，系统提供已有的紧急镇定：资金 -20、污染 -5，可负债，且没有律令持续期。颁布成功提示不代表漏洞已经触发；持续时间和漏洞仍由 C++ 按逻辑回合处理。

为了使代价在“白天营业、夜间固定补给、历史暂缓”的新循环中实际生效，**仅 `DT_Decrees_UI`有以下四处转换**。原 `DT_Decrees`不变，显示用 `CostText`也同步更新。

| 行名／律令 | 原代价 | UI 专用代价与原因 |
| --- | --- | --- |
| `bronze_01` 静阅律 | 当晚收入 -20% | 立即资金 -10；本轮没有夜间销售收入。 |
| `bronze_02` 闭门律 | 当晚顾客 -1 | 立即资金 -8；本轮无夜客，且白天保持 3 槽。 |
| `bronze_03` 燃烛律 | 阅读灵能收益 -20% | 立即资金 -10；本轮直接夜结恢复灵能，没有阅读入口。 |
| `gold_01` 无名律 | 删除一条历史线索 | 立即资金 -40；历史延期，不能以未提供的线索阻止使用。 |

上表只替换对应 `CostEffect`，原灵能消耗、污染降低、其他效果和漏洞继续保留。`silver_01`闭架律仍标记一册秘密书被篡改；本轮无阅读入口，因此其阅读额外污染暂时不会通过该界面触发，但后续解封及污染效果不被删除。无名律的永久经营惩罚仍保留；其中客流减少值在固定 3 槽模式下不改变人数，租金惩罚仍有效。这些差异不是悄悄改动原 Release 数值。

数值执行依据是 `CostEffect/Effects/LoopholeEffect`等字段；`CostText/EffectText/LoopholeText/Text`只负责显示。改代价时要同步修改执行字段和文字，仅改说明不会改变扣费。

**律令尚未完全完成界面验收：**七条核心效果、候选筛选、支付与弹窗调用可用；剩余持续期（TTL）、剩余冷却尚无界面展示，实际漏洞反噬触发时也缺少专门播报。固定 3 槽下，无名律的客流减少分支不改变实际人数；闭架律的额外阅读污染尚无阅读入口可触发。不能把“颁布成功”提示或核心逻辑测试通过理解为这些体验已完成。本次场景与到场调整没有再次更改律令参数。

## 6. 如何继续编辑与目前范围

双击任一 WBP，**Designer**内可以编辑真实控件树、布局、背景、文字和按钮；**Graph / EventGraph**内可以修改真实 `OnClicked`、接口调用和页面切换连线。书卡是可复用子控件，通过其 `BookId`关联书籍，`CoverTexture`关联实际纹理；`BookCover.Brush`绑定调用 `MakeBookCoverBrush`，外层 ScaleBox 保持封面比例。当前根页面使用 1920×1080 设计尺寸并由 ScaleBox适配视口。

WBP负责页面、交互顺序、气泡、按钮事件和反馈显示；`ShopPresentationLibrary`只提供文本、队首、可用状态和阶段到页面的映射，不创建控件；`ShopRunSubsystem/ShopEconomy/ShopCustomers/ShopDecrees`负责唯一状态、计时、资源、随机、事务、污染、律令和结局。不要在 WBP 复制一份真实金钱或库存再自行加减。

`WBP_SurfaceShop`只显示原背景的一层区域，**没有裁改或另存原图文件**。`FirstFloorFrame`是位于根设计坐标 `(0,130)`、大小 `1920×900`的 ScaleBox；其内 SizeBox 固定为 `1440×675`，内容 Canvas `FirstFloorScene`裁剪到自身边界。原 `1920×1080`背景放在该 Canvas 的 `(-240,-405)`，因此可见原图范围为 `x=240..1680、y=405..1080`。整个一层场景等比放大，原背景中的柜台随之保留。
